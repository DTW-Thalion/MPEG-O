sub-phase per [`docs/workbench-client/W5-plan.md`](W5-plan.md).

Sixth W5 sub-phase. JavaFX surfaces wrap the W4 `SessionsClient`
SDK -- no new wire surface, no new SDK code.

## Server-side reuse (no new wire surface)

W5.6 builds on the W4 endpoints already wrapped by the SDK:

```
POST   /v1/sessions            -- create (via SessionsClient.create(...))
GET    /v1/sessions[?status=X] -- list (via SessionsClient.list(...))
GET    /v1/sessions/{id}       -- get  (via SessionsClient.get(id))
DELETE /v1/sessions/{id}       -- terminate (via SessionsClient.terminate(id))
```

The attach URL is built by the W4 `SessionProxy.url(...)` helper.

## Decision: attach via the operator's own client (option b)

Per the W5-plan open-question 2 decision: the interactive
attach happens through the operator's own WS-capable client
(the CLI `ttio sessions attach` or a terminal), not an embedded
JavaFX WebView. The session list copies the `wss://` attach URL
to the clipboard + shows it in a copyable dialog. The embedded
Jupyter-in-WebView path (spec section 7.4 step 3 option a)
remains a v1.1 tio-browser enhancement.

This avoids:
- Bundling a browser engine (JavaFX WebView is heavyweight + has
  no native WS-binary support for the proxy protocol).
- Coupling the GUI to a specific engine's HTTP UI.

## Tests

### tio-browser (`SessionLauncherTest`) - 15 tests

- `parseCommand`: whitespace split; blank/null -> empty list.
- `parseBindMounts`: basic host:container; drops `:mode` suffix;
  skips blank lines; rejects missing/leading/trailing colon.
- `parseEnv`: KEY=VALUE; value-with-equals preserved; skips
  blank lines; rejects no-equals / leading-equals.
- `isValidProject`: blank rejection.

### tio-browser (`SessionListTest`) - 4 tests

- `attachUrl` builds the WS proxy URL for a running session
  (wss + ws scheme variants).
- `attachUrl` returns null for non-running / null args.
