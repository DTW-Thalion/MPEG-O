## Server-side reuse (no new wire surface)

W5.5 builds on the W3 endpoints already wrapped by the SDK:

```
GET    /v1/pipelines           -- list (via PipelinesClient.list())
GET    /v1/pipelines/{id}      -- get  (via PipelinesClient.get(id))
POST   /v1/jobs                -- submit (via JobsClient.submit(...))
GET    /v1/jobs[?status=X]     -- list (via JobsClient.list(...))
DELETE /v1/jobs/{id}           -- cancel (via JobsClient.cancel(...))
GET    /v1/jobs/{id}/events    -- SSE tail (via JobsClient.events(...))
```

## v1.0 scope: raw JSON for pipeline inputs / params

The W5-plan said "parameter form driven by the pipeline
definition's parameter schema." Schema-driven form rendering is
a significant subsystem (resolve a JSON Schema -> JavaFX controls
+ validators). v1.0 of W5.5 ships raw JSON textareas with a
top-level-object validator, plus a read-only pipeline-schema
preview pane so the operator can see the expected shape.

Schema-driven rendering is a v1.1 enhancement; the underlying
SDK already accepts `Map<String, Object>` so no client code
change will be needed beyond replacing the textarea pair with a
form-generator.

## Tests

### tio-browser (`PipelineLauncherTest`) - 9 tests

- `isValidJsonObject`: accepts empty + populated objects; rejects
  blank / null / array / scalar / malformed.
- `renderSchemaPreview`: identifier + version + project + owner +
  engine-pin + inputs / outputs schemas all surface; empty
  schemas render as `(none)`; engine-pin omitted when null/empty;
  stable for identical inputs.

### tio-browser (`JobMonitorTest`) - 6 tests

- `formatTimestamp`: UTC ISO-8601 for positive seconds; blank for
  null / 0 / negative.
- `filterValue`: resolves `(all)` / `""` / `null` to `null`;
  passes through known statuses verbatim.

### tio-browser (`JobEventsViewTest`) - 7 tests

- `formatFrame`: event-name + key=value pairs; handles empty data
  map; renders `[?]` for a null event name.
- `isTerminalEvent`: detects completed / failed / cancelled;
  false for queued / starting / running; false for non-state
  events (e.g. `job.heartbeat`); false for missing status; false
  for null.
