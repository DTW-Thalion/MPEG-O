# W5.4 progress

Status snapshot for the **Cohort Query Builder** sub-phase per
[`docs/workbench-client/W5-plan.md`](W5-plan.md).

## Status (2026-05-19): COMPLETE -- in review

Fourth W5 sub-phase. Visual predicate-composition window driving
the W3 `CohortQuery` SDK; tio-browser-only (no new SDK code
needed -- the W3 predicate AST is the source of truth).

## Server-side reuse (no new wire surface)

The v1.0 server exposes two cohort endpoints (per
`tti-workbench-server/Source/HTTP/handlers/TTIOWBCohortsHandler.{h,m}`):

```
POST /v1/cohorts/query           -- paginated query rows
POST /v1/cohorts/preview-count   -- count-only variant
```

There is **no** `POST /v1/cohorts` endpoint (i.e., no "persist
cohort by name") in v1.0. The W5-plan mentions a
`CohortClient.create(name, predicate)` but the server doesn't
support it yet; the "Save as cohort..." button is deferred to
W5.4 follow-up (v1.1 server work).

W5.4 wraps the existing endpoints with a JavaFX form that
constructs a `CohortPredicate` (W3 SDK type) from operator-typed
row inputs.

## Deliverables

### tio-browser GUI (`tio-browser/.../workbench/`)

| File | Purpose |
|---|---|

JavaFX-property-backed fields (kind / field / op / rawValue). `toPredicate()` builds the matching `CohortPredicate` leaf; `coerceValue(raw, op)` converts the raw text input to a typed value (int / double / bool / string / comma-separated list for `in`). |

## Client-side rule enforcement

W5.4 mirrors two v1.0 server rules client-side so the user gets a
visible error instead of a 400 from the daemon:

1. **`phenotype` rejected under `OR` / `NOT`.** Captured in
   `buildPredicate`; throws `IllegalStateException` before any
   network round-trip.
2. **`NOT` requires exactly one leaf.** Same -- caught client-side
   with a clear message.

## v1.0 scope: flat leaf list under a single composite root

A true tree-style editor (nested composites, drag-drop reorder)
is a v1.1 enhancement. The current scope -- one AND / OR / NOT
root with N leaves -- covers the workplan's example cohort query
("project=alpha AND diagnosis=Alzheimer's") and the typical
single-predicate flows.

Nested composite trees are still buildable via the W3 SDK
directly (e.g. `CohortPredicate.and(a, CohortPredicate.or(b, c))`)
-- the GUI just doesn't surface them in v1.0.

## Tests

### tio-browser (`CohortLeafRowTest`) - 13 tests

- `coerceValue` parses ints / doubles / bools / strings.
- `coerceValue` for `exists` defaults blank to TRUE.
- `coerceValue` for `in` builds a typed list from a
  comma-separated string.
- `toPredicate` builds the right `CohortPredicate` subclass per
  kind.
- `toPredicate` rejects blank field with `IllegalArgumentException`.
- `Kind.fromLabel` round-trips every enum value.

### tio-browser (`CohortQueryBuilderTest`) - 11 tests

- AND with one leaf collapses to the leaf (no wrapper).
- AND with two leaves builds an `AndPredicate`.
- AND allows phenotype.
- OR with two leaves builds an `OrPredicate`.
- OR rejects phenotype.
- NOT with one leaf builds a `NotPredicate`.
- NOT rejects zero / multiple leaves.
- NOT rejects phenotype.
- Empty leaf list rejected.
- Unknown composite rejected.
