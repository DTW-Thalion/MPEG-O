# W5.1 progress

Status snapshot for the **Connection Manager** sub-phase per
[`docs/workbench-client/W5-plan.md`](W5-plan.md).

## Status (2026-05-19): COMPLETE -- in review

First substantive W5 PR. Adds the foundation that every other W5
panel will hang off: a workbench connection holder + login flow +
status indicator.

## Deliverables

### Main code (`tio-browser/src/main/java/global/thalion/ttio/browser/workbench/`)

| File | Purpose |
|---|---|
| `ConnectionState.java` | Four-state enum (`DISCONNECTED` / `CONNECTING` / `CONNECTED` / `FAILED`). |
| `ConnectionListener.java` | Functional interface; `onStateChanged(state, message)`. |
| `ConnectionManager.java` | Singleton holding the `WorkbenchClient` + state machine. Public methods: `connect(url, auth)`, `disconnect()`, `state()`, `isConnected()`, `client()`, `session()`, `addListener/removeListener`. Thread-safe via `CopyOnWriteArrayList` for listeners and `volatile` for state. |
| `LoginDialog.java` | Modal `Stage`-based form with server URL + username + password + TOTP fields. Static validators (`isValidUrl`, `isValidTotp`, `isValidUsername`, `isValidPassword`). `Bindings.createBooleanBinding` keeps the Connect button disabled until valid; the worker `Task<Session>` calls `ConnectionManager.connect()` off the FX thread. |
| `StatusIndicator.java` | Small `HBox` (coloured `Circle` + `Label` + `Tooltip`) for the status bar. Subscribes to `ConnectionManager`; renders four colour states (grey / yellow / green / red). |

### MainWindow integration

- New `Workbench` menu between `Transport` and `Tools`. Items:
  `Connect…`, `Disconnect`, `Status…`.
- Status bar gains a right-aligned `StatusIndicator.node()`.
- `dispose()` detaches the indicator's listener.
- `showWorkbenchStatus()` is a modal `Alert` summarising the
  current session (endpoint, user, provider, projects,
  capability count, session id). When disconnected, surfaces the
  last failure message.

## Tests

### Pure-unit (no FX toolkit)

`ConnectionManagerTest` — 8 tests:
- initial state is DISCONNECTED
- successful connect transitions through CONNECTING -> CONNECTED
- failed connect transitions through CONNECTING -> FAILED and rethrows
- disconnect from CONNECTED -> DISCONNECTED (with listener fire)
- disconnect from DISCONNECTED is idempotent
- `removeListener` stops notifications
- a listener that throws does not block siblings
- reconnect after FAILED succeeds

`LoginDialogTest` — 9 tests covering the static validators
(URL scheme/bare host/spaces/colon, TOTP 6-digit-exactly +
non-digit rejection, username blank rejection, password empty
rejection).

### TestFX (Monocle headless)

`StatusIndicatorSmokeTest` — 3 tests:
- DISCONNECTED renders grey + descriptive label
- CONNECTED transitions render green + username in label
- FAILED transitions render red + error message in tooltip
