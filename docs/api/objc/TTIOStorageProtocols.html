Software documentation for the TTIOStorageDataset protocol

TTIOStorageDataset

Declared in:
TTIOStorageProtocols.h

Conforms To: NSObject (NSObject)

Declared In: Providers/TTIOStorageProtocols.h

A typed array (or compound record array) stored under a TTIOStorageGroup. 1-D is the common case; N-D is supported for image cubes and 2-D NMR data.

API status: Provisional.

readAll: 

- (id) readAll: (NSError**)error;
Read the entire dataset. Return type varies by backend: - Primitive datasets: NSData of length * sizeof(element). - Compound datasets (all backends): NSArray<NSDictionary *> where each dict maps field name to boxed value. The ObjC reference implementation returns this shape for both HDF5 and SQLite providers, so callers do not need to branch on provider type. The universal helper -readRows: returns the same value and is provided for cross-language parity with Python and Java. @param error On failure, populated with an ``NSError``. May be ``NULL``. @return Backend-specific value as documented above, or ``nil`` on failure.

readCanonicalBytes: 

- (NSData*) readCanonicalBytes: (NSError**)error;
Returns the dataset contents as a byte stream in the TTIO canonical layout. Semantics: - Primitive numeric: little-endian packed values. - Compound: rows in storage order; fields in declaration order. VL strings as u32_le(length) || utf-8_bytes. Numeric fields little-endian. Signatures and encryption consume this so a signed or encrypted dataset verifies identically regardless of which provider wrote it. Required on the protocol because signature/encryption callers can never silently skip the canonicalisation step. Returns nil on read failure; populated NSError on failure.

readRows: 

- (NSArray*>*) readRows: (NSError**)error;
Backend-agnostic compound read. Returns NSArray<NSDictionary *> for compound datasets, nil + NSError for primitives. ObjC compound readers already return the NSDictionary shape universally, so most implementations are a trivial forwarder to -readAll: . Required on the protocol so that custom provider implementations that omit it fail at compile time rather than silently at runtime via doesNotRecognizeSelector:.

May be ``NULL``. @return Slice in the same shape as ``-readAll:`` (NSData for primitive, NSArray of NSDictionary for compound), or ``nil`` on failure.

TTIOStorageGroup

Declared in:
TTIOStorageProtocols.h

Conforms To: NSObject (NSObject)

Declared In: Providers/TTIOStorageProtocols.h

A named directory of sub-groups and datasets. Groups form a hierarchical namespace; every provider exposes at least one root group via TTIOStorageProvider. Upper-layer objects ( TTIOSpectralDataset, TTIOAcquisitionRun,...) navigate the tree exclusively through this protocol.

API status: Provisional.

Cross-language equivalents:
Python: ttio.providers.base.StorageGroup

Software documentation for the TTIOStorageProvider protocol

TTIOStorageProvider

Declared in:
TTIOStorageProtocols.h

Conforms To: NSObject (NSObject)

Declared In: Providers/TTIOStorageProtocols.h

Storage backend entry point. A provider opens a backing store (HDF5 file, in-memory tree, Zarr store, SQLite database, etc.) and exposes its root TTIOStorageGroup. Providers are selected by scheme-based routing via -supportsURL: or named explicitly through TTIOProviderRegistry. Upper layers talk only to the protocols and stay backend-agnostic.

API status: Provisional.

Cross-language equivalents:
Python: ttio.providers.base.StorageProvider
Java: global.thalion.ttio.providers.StorageProvider
