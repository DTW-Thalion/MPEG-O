# GPU V6 Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Vulkan qualities-encode engine for M94.Z V6 that produces
byte-identical output to the CPU coder, is used only on explicit opt-in, and
falls back to the CPU path in every failure case.

**Architecture:** An engine abstraction in `libttio_rans` with two
implementations. The CPU engine is the existing segment loop. The GPU engine
lives in a separate shared library that is dlopened only when `TTIO_GPU=force`
is set, and encodes whole blocks by running one chain per GPU invocation.
`m94z_qual.c` asks the GPU engine for a slot per block and falls back to the
CPU engine immediately if it cannot get one. Nothing above the codec layer
knows a GPU exists.

**Tech Stack:** C11, pthreads, Vulkan 1.2 compute, GLSL compiled to SPIR-V at
build time, CMake. Correctness is developed and gated under the lavapipe
software rasteriser on Linux; NVIDIA hardware on Windows is used only for
performance measurement.

**Spec:** `docs/superpowers/specs/2026-08-20-gpu-v6-phase2-encode.md`

## Global Constraints

- Byte identity is the ship gate: GPU output must equal CPU output for every
  block of every reference corpus, and across repeated runs.
- Encode only. GPU decode, sequences rANS and an automatic selection mode are
  Phase 3 or later and must not appear in this work.
- `TTIO_GPU` defaults to `off`. With `off`, no probe, no dlopen and no log
  line. The only other accepted value is `force`.
- The writer pins V6 only when the engine actually initialised. Writing V6
  with no engine gives larger files and no speed, so it must not happen.
- V4 and V5 are shipped, byte-frozen formats. `sm_model.h`, `fqzcomp_qual.c`
  and `fqzcomp_seqctx.c` must not change.
- The V6 wire format is settled by Phase 1 and must not change.
- No AI attribution anywhere; no change-describing comments; commit subjects
  short imperative ("engine: ...", "vk: ...", "docs: ...").
- Apply kernel edits to `native/` only; `python/_native` is generated.
- Build the native tree with `cmake --build native/_build -j` and run test
  binaries directly. Never gate on bare `ctest`.
- Python tests: `TTIO_RANS_LIB_PATH=<abs>/native/_build/libttio_rans.so
  .venv/bin/python -m pytest ...`. Use a script file with literal paths;
  `$PWD` inside `wsl bash -lc` expands to the Windows working directory.
- Worktree `~/TTI-O.worktrees/block-parallel`, branch `gpu-engine-v6`.
  PR #307 is a draft and must not be merged.

## Dev loop

Correctness runs entirely on Linux. `vulkaninfo` there reports lavapipe, a
software rasteriser, which runs the real SPIR-V kernel and has been confirmed
to produce byte-identical output to the CPU coder. It is slow, so tests use a
handful of chains. Performance numbers require the NVIDIA device, which is
reachable only from native Windows:

```
glslangValidator -V native/gpu/v6_chain.comp --vn v6_spv -o /tmp/v6_spv.h
gcc -O2 -Wall -I/tmp -o /tmp/spike native/gpu/... -lvulkan   # Linux, lavapipe
```

MSYS2's `glslangValidator` is broken on this machine
(STATUS_ENTRYPOINT_NOT_FOUND); compile SPIR-V under WSL with `glslang-tools`
and copy the generated header. SPIR-V is host independent.

  no spike precedent; the fault-injection hook exists so the loss path is
  tested rather than reasoned about.
